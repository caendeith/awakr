# Awakr — спецификация v1.1 (UX-пасс, коды миссии, свои звуки, темы)

Дополняет `docs/spec.md` (v1.0.0). Всё, что здесь не оговорено, действует по v1-спеке.
Срок жизни: релиз **v1.1.0** (versionCode 2).

## 1. Цель и не-цели

### 1.1 Цель
Сделать ежедневное использование Awakr быстрым и приятным: пакетные действия с будильниками,
минимум тапов на частые операции, «живой» интерфейс; миссия-код должна работать и с фотографии
кода (а не только с потокового превью) и сохранять снимок; будильник должен играть **свою музыку**
из памяти телефона или один из семи встроенных звуков; приложение должно поддерживать тёмную и
светлую темы.

### 1.2 Не-цели v1.1
- Виджеты, Wear OS, «умный подъём», запись звука с микрофона, облачная синхронизация.
- Динамический цвет (Material You) — остаётся кандидатом на v2.
- Произвольные форматы кроме QR/штрихкодов (DataMatrix/Aztec/PDF417) — сознательно вне объёма:
  спрашивали только «куар и штрихкод».
- Смена архитектуры плагинов (SDK остаётся v1, кроме аддитивного поля в манифесте, если понадобится).

### 1.3 Ограничения
Без `INTERNET`, без рекламы и аналитики, MIT, minSdk 26, compileSdk/targetSdk 36, Pixel 7 Pro / Android 17
— эталонное устройство. Все строки — en (default) + ru.

## 2. UX: список будильников (Home)

### 2.1 Долгое нажатие → режим выбора
- Долгое нажатие на карточку включает **режим выбора**: карточки получают чекбокс, верхняя панель
  меняется на контекстную («Выбрано: N»), Home-FAB скрывается.
- Действия в контекстной панели: **Включить**, **Выключить**, **Дублировать**, **Удалить**,
  «Выбрать все» в меню «⋮», выход — «×» или системный «Назад».
- Долгое нажатие даёт тактильный отклик (`HapticFeedbackType.LongPress`).
- Обычный тап по карточке (вне режима выбора) — редактор, как сейчас.
- Тап по карточке в режиме выбора — переключает её выбор.

### 2.2 Меню «⋯» на карточке
Видимая точка входа для одиночных действий (жест не должен быть единственным путём):
**Изменить**, **Дублировать**, **Пропустить следующее**, **Включить/Выключить**, **Удалить**.
Реализация — `DropdownMenu`, тач-таргет ≥ 48 dp.

### 2.3 Свайп по карточке (настраиваемый)
- Левый свайп выполняет действие, выбранное в настройках: **Удалить** (по умолчанию),
  **Включить/Выключить**, **Ничего**.
- Удаление и пакетные операции показывают `Snackbar` с **Undo** (5 с) — удаление мягкое:
  строки помечаются `deleted_at` и физически удаляются при следующем старте, чтобы Undo работал
  без гонок с планировщиком.
- В режиме выбора свайп отключён.

### 2.4 Порядок и анимации
- Кнопка «Порядок» в меню Home включает режим перестановки: карточки перетаскиваются за ручку,
  порядок сохраняется в `alarms.sort_order`; вне режима список сортируется по `sort_order`,
  затем по времени.
- Анимации: `animateItem` для вставки/удаления/перестановки, spring-переходы контекстной панели,
  плавная смена цифр отсчёта, «пилюля» отсчёта с morph-анимацией ширины.

## 3. Редактор будильника

- Время: крупный M3-пикер в боттомшите, чипы быстрого сдвига **+5 / +15 / +30 минут**,
  превью следующего срабатывания (уже есть).
- **Звук**: выпадающий список — 7 встроенных тонов + «Свой файл…» (системный выбор аудио).
  Выбранный файл копируется в приватное хранилище приложения (`files/sounds/<uuid>.<ext>`), чтобы
  будильник не сломался, если исходник удалят. Рядом — «Прослушать».
- **Миссия**: пресеты одним тапом — «Математика · легко», «Тряска 30 с», «Код», «Текст».
- **Пропустить следующее срабатывание** — разовый флаг, не выключает будильник.
- **Дублировать** доступно из меню и из редактора (создаёт копию со сдвигом «+1 час», если время занято).

## 4. Миссия-код (переименование `mission-qr` → `mission-code`)

### 4.1 Форматы
Только популярные: **QR**, **EAN-13**, **EAN-8**, **UPC-A**, **CODE-128**. Для EAN/UPC — проверка и
догенерация контрольной цифры; невалидное содержимое не сохраняется.

### 4.2 Способы решения: наведение камеры (основной) и снимок (необязательный)
- **Основной путь — просто навести камеру.** Живое превью уже декодирует кадры автоматически;
  как только распознан ожидаемый код (или любой поддерживаемый, если содержимое не задано) —
  миссия решена. Никакой съёмки не требуется.
- **Снимок — опция, а не обязанность.** Кнопка **«Сфотографировать»** нужна для двух случаев:
  код мелкий/бликует и живой поток не ловит, или хочется сохранить кадр. Нажатие делает
  `ImageCapture`, декодирует кадр и сверяет его с ожидаемым.
- **Сохранение кадра** происходит только по нажатию кнопки: `files/shots/<timestamp>.jpg` +
  запись в MediaStore (Pictures/Awakr) там, где это доступно без разрешений (API 29+).
  На 26–28 — приватное хранилище + «Поделиться». После сохранения — превью и подпись «Фото сохранено».
- Никаких разрешений сверх CAMERA не требуется; сохранение не блокирует решение миссии.
- В редакторе: предпросмотр кода, **«Сохранить PNG»** (SAF `CreateDocument`), **«Поделиться»**.
- Если содержимое не задано — принимается любой код поддерживаемого формата.

### 4.3 Техника
`MultiFormatReader` с `POSSIBLE_FORMATS` по выбранному формату; из `ImageProxy` — существующий
`QrFrame`, из `Bitmap` — `RGBLuminanceSource`; декод снимка — в `Dispatchers.Default`,
даунскейл до ≤ 2048 px. `MultiFormatWriter` для генерации.

## 5. Звуки

- Семь встроенных тонов в `res/raw` (синтезированы нами, clean-room): *Chime, Marimba, Bell,
  Digital, Sunrise, Alarm, Pulse*. Формат WAV/OGG моно ≤ 6 с, зацикливание через MediaPlayer.
- `SoundRepository`: `builtin:<id>` | `file:<path>`; разрешение при звонке с fallback на
  «звук по умолчанию» → Chime.
- Настройки: «Звук по умолчанию», «Длительность „Отложить"» (5–30 мин, шаг 5).
- Существующие будильники миграции не требуют: пустое значение = звук по умолчанию.

## 6. Темы

- `theme_mode`: **system** (по умолчанию) / **dark** / **light**; DataStore.
- Тёмная палитра v1 сохраняется; светлая — тот же янтарный акцент (`#B87500` для контраста на светлом),
  фон `#FBF8F4`, поверхность `#FFFFFF`, контейнер `#F2EDE6`.
- Переключение мгновенное (Compose recomposition), без перезапуска.

## 7. Данные и миграция (Room v1 → v2)

```sql
ALTER TABLE alarms ADD COLUMN sound_id TEXT NOT NULL DEFAULT '';
ALTER TABLE alarms ADD COLUMN sort_order INTEGER NOT NULL DEFAULT 0;
ALTER TABLE alarms ADD COLUMN skip_next_at INTEGER;
ALTER TABLE alarms ADD COLUMN deleted_at INTEGER;
```
DataStore: `theme_mode`, `swipe_action`, `default_sound`, `default_snooze_minutes`.

## 8. Тесты

- `CodePayloadTest`: контрольная цифра EAN-13/EAN-8/UPC-A, генерация CODE-128/QR, отказ на мусоре.
- `CodeImageTest`: декод `Bitmap` (QR + EAN-13), повёрнутые снимки.
- `AlarmOrderTest`: чистая функция перестановки и сортировки (`sort_order`, затем время).
- `SkipNextTest`: `NextOccurrence` с `skip_next_at` — пропускает ровно одно вхождение, дальше обычный ряд.
- `SoundResolutionTest`: `file:` → `builtin:` → default.
- Headless-проверки: `./gradlew test :app:lintDebug` зелёные.

## 10. Риски

| Риск | Мера |
|---|---|
| Свои WAV-звуки раздувают APK | моно, ≤ 6 с, сжатый OGG/WAV; целевой release ≤ 8 МБ |
| `ImageCapture` на некоторых ROM-ах медленный | декод в фоне, таймаут 3 с, кнопка «Попробовать снова» |
| Миграция Room ломает данные | явный `Migration(1,2)` + тест на пустой и заполненной БД |
| Свайп конфликтует с прокруткой | только горизонтальный свайп у края, drag-реордер отдельным режимом |
| Undo после удаления гоняется с планировщиком | мягкое удаление (`deleted_at`), планировщик игнорирует помеченные |

Отклонения от спеки и почему:

- **Лист выбора звука не закрывается по тапу** — сделано намеренно: так можно прослушать несколько тонов подряд (радио-отметка сразу показывает выбор, звук играет), лист закрывается свайпом/тапом по затемнению.
- **Снимок сохраняется только при успешном распознавании** — сохранять каждый неудачный кадр в галерею было бы мусором; при неудаче показывается «Код не распознан, попробуйте ещё раз».
- **Повторяющиеся будильники теперь перепланируются при закрытии звонка** — в v1 это происходило только при старте/boot, что ломало ежедневные будильники; правка в `AlarmRingService.finish()`.
- **Смена формата кода больше не оставляет несовместимый payload** — `CodePayload.ensureEncodable` перегенерирует код под выбранный формат вместо пустого превью.
- **Кнопки под кодом переносятся, а не сжимаются** — `FlowRow` вместо `Row`.

Не проверено физически (нужен второй экран/принтер, см. `docs/manual-qa.md`): сканирование настоящего кода камерой, реальная тряска телефона, звонок при PIN-локскрине; декодирование кадров и логика покрытия — юнит-тестами и эмуляцией кадров.
